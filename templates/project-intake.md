# Project Intake — Template v1

## 1. What are we building?

Describe the product, app, agent, automation, dashboard, Web3 tool, or business system.

## 2. Who is it for?

Define the target user.

Include:
- user type
- current pain
- technical level
- buying intent if relevant

## 3. What problem does it solve?

Describe the real problem, not just the feature idea.

## 4. What is the MVP?

Define the smallest useful version.

MVP must include:
- core feature
- main user flow
- validation method
- success criteria

## 5. What is not included now?

List things intentionally postponed.

## 6. Required tools

Define required tools:

- frontend
- backend
- database
- auth
- payments
- AI model
- agent runtime
- APIs
- deployment target
- QA tools

## 7. Known constraints

Examples:
- mobile-only workflow
- Termux
- limited budget
- no laptop
- no API keys yet
- no deploy target yet
- private repo
- public demo required

## 8. Missing information

If anything depends on real setup, ask Osa.

Do not guess:
- repo names
- paths
- APIs
- keys
- deployment target
- architecture decisions

## 9. First execution decision

Choose one:

- PLAN
- AUDIT
- BUILD
- TEST
- DEPLOY
- STOP

## 10. Next Concrete Step

Define one next action.
